1
Integración
Timeline unificado del paciente
pandas ~6h
Qué resuelve
RISA tiene los datos repartidos en varios archivos (signos vitales, laboratorio, wearables, medicamentos, contexto), cada uno con su propia estructura y frecuencia. Esta capa apila todo en una sola tabla larga con un esquema común — un append, no un join.
Qué se limpia
Normalización de unidades (°C/°F, mg·dL/mmol·L), deduplicación de retransmisiones, y marcado de data_origin: observed/imputed.
Ejemplo
Paciente 347: 200 signos vitales (c/15min) + 3 labs + 500 lecturas wearable + 2 medicamentos → ~705 filas en una sola tabla, cada una con su origen y timestamp conservados.
salida → timeline_df
2
Features
Indicadores por paciente y ventana temporal
pandas · numpy ~6h
Qué resuelve
Un valor crudo no dice nada solo. Esta capa calcula z-score personal (vs. baseline propio, no poblacional), tendencias corta/media, persistencia, calidad y contexto.
Regla crítica
Todo se calcula con available_datetime ≤ T mediante una función central — garantiza cero leakage temporal en todo el pipeline.
Ejemplo
Pac. 347 a las 14:00h: FC=112 (z-score personal=+2.4), tendencia corta=+0.8 (subiendo), persistencia=4 puntos, quality=0.9, sin actividad física registrada.
salida → features_df
3
Detección
Reglas explícitas + Isolation Forest en paralelo
pandas · sklearn ~8h
Motor de reglas
1) |zscore| > 2.0 → 2) persistencia ≥ 3 → 3) ≥2 variables co-desviadas. 100% explicable, sin entrenamiento.
Isolation Forest
No supervisado, sin etiquetas. Detecta combinaciones raras que las reglas no anticiparon (ej. 4 variables levemente desviadas).
Ejemplo
Pac. 347: reglas lo detectan (FC+SpO2 co-desviadas 4pts) Y anomaly_score=0.82. Pac. 589: solo el ML lo detecta — ninguna variable pasa z-score>2 individualmente.
salida → candidate_signals_df
3+
Trayectorias temporales mejora wow
Clasificar la forma de la evolución, no solo el estado puntual
dtaidistance +4-6h
Qué aporta
Detecta la forma de la evolución (deterioro sostenido, recaída, ruido, estable), no solo el estado en un instante. Ataca "análisis temporal" (6 pts) con algo que el jurado no espera.
Cómo funciona
Comparar la serie del paciente contra arquetipos de referencia con Dynamic Time Warping. Alternativa barata: k-means sobre features de forma.
Ejemplo
Pac. 347: distancia DTW=2.1 a "deterioro sostenido" vs 8.4 a "estable" → se clasifica como deterioro progresivo, reforzando la urgencia.
Riesgo
Esfuerzo alto. Solo intentar si los pasos 1-6 base ya corren de punta a punta y quedan ≥8h.
agrega a → candidate_signals_df.trajectory_type
4
Priorización
Supresión de ruido + score + atenuación por contexto
pandas · numpy ~4h
A · Supresión
Sin persistencia ≥3 o con quality_score < 0.4 → descartar antes de calcular nada. Lo eliminado nunca aparece en signals.csv.
B · Score
risk_score = 0.4×magnitud + 0.35×co-ocurrencia + 0.25×persistencia. Fórmula fija y documentada, no optimizada con ML.
C · Contexto
Medicación activa → ×0.7, actividad física → ×0.8 (atenúa, no elimina). Reglas duras nunca se degradan por debajo de HIGH.
Ejemplo
Pac. 347: score=0.735 sin contexto → HIGH. Pac. 201: score=0.68 con medicación reciente → 0.68×0.7=0.476 → MEDIUM, con nota "atenuado por contexto".
salida → signals_draft_df
5
Ranking wow recomendado
Cola de prioridad + métrica anti-alertas
pandas ~3h
Cola de prioridad
Ordenar señales por risk_score + top variables por señal. Responde "¿por qué A antes que B?" con una tabla, sin abrir código.
Métrica anti-alertas
Comparar contra baseline de umbral fijo: "reducción del 86% en alertas" — número concreto para el pitch, ~15 líneas de pandas.
Ejemplo
#1 Pac.347: FC↑4h+SpO2↓ · #2 Pac.112: PA↓+creatinina↑ · #3 Pac.589: FC↑ (atenuado: actividad).
salida → Ranking + % reducción de alertas

6+
Redacción con LLM trazable mejora wow
El LLM reformula, nunca inventa cifras
API Claude +2-3h
Qué aporta
Redacción natural sin sacrificar trazabilidad. Se guardan ambas versiones y una atribución porcentual por variable.
Cómo funciona
Prompt: "reformula sin modificar cifras". Guardar explanation_raw + explanation_llm.
Ejemplo
Plantilla → "FC elevado (2.3 SD) durante 4h..." · Reformulado → "La frecuencia cardíaca se mantiene notablemente elevada desde hace 4 horas..." — mismos números.
Riesgo
Esfuerzo medio. Prompt engineering cuidadoso para que no agregue matices no sustentados.
agrega a → explanation_llm + attribution_pct
6+
Auditoría inversa mejora wow
Reconstruir la cadena completa y probar sensibilidad
pandas +3-4h
Qué aporta
Responde "¿qué tan confiable es esto con datos imperfectos?" — exactamente lo que RISA está diseñado para testear.
Cómo funciona
Cadena inversa: prioridad → score → regla → feature → dato fuente. Recalcular con imputación alternativa.
Ejemplo
Pac. 201 (MEDIUM, confidence 0.6): con otra imputación el score sube a 0.71 → cambiaría a HIGH → se marca "sensible a imputación".
Riesgo
Esfuerzo alto pero fácil de recortar sin romper el pipeline base — es una vista opcional, no una dependencia.
agrega a → audit_trail() + sensitivity_flag
Regla de decisión
Las 6 etapas base son obligatorias — sin ellas el sistema no cumple el formato de entrega ni corre de punta a punta. Las mejoras wow se agregan solo si el pipeline base ya corre sólido con datos reales y queda margen de al menos 8 horas. Ninguna reemplaza al pipeline base — todas se apilan encima sin romperlo.
Ranking (paso 5) > Trayectorias > LLM trazable > Auditoría
